BrandCraft
Generated: 2026-11-11 (trimmed index: map + traps. Long-form record lives in summarybkp.txt)
Purpose: browser-only Minecraft skin renderer. Drop a skin -> 8 preset cards (share codes in src\preset\slots.txt) -> tune any card on the edit page (46 sliders + 1 halftone chip over the same codec) -> download screen -> save the PNG (riso print baked in) at 1K/2K/4K. Below the grid: 4 banner cards (2 busts + wordmark, one shared refresh) that export 2560x1440 / 1546x423 strip.

0. Reader contract
- Trust the map, verify before editing: paths and names here are maintained by hand, so confirm a file before a mutating edit. Grep is cheap; a stale assumption is not.
- Single target: map request -> one file via section 1. Open that file only, by line range.
- Surgical diffs: minimal contiguous blocks, exact anchors. Never rewrite a working file.
- Hands off runtime: never kill, restart, or probe servers, daemons, ports, sockets.
- Values live in code: palette in src\styles\tokens.css, geometry in src\styles\app.css, springs in src\motion.ts. This file never restates a value.
- Deeper detail: docs\design.md (why + traps), docs\instruction.md (share-code spec), docs\summarybkp.txt (every CSS class, every module function, token tables).

2. Data
Storage: none. No backend, no persistence, no cookies, no localStorage; the grid look is re-rolled per load unless ?r=<uint> pins the seed.
Pipeline: File input -> FileReader.readAsDataURL -> store.skinUrl -> shared offscreen SkinViewer (master = size*2 clamped 1024..4096) -> screenshot("png") -> 2D canvas crop to the preset bust box -> output size -> data URL -> <img> card src / <a download> href.
Cutout pipeline: same viewer, full body, no animation (bind pose), zoom 40 -> screenshot -> scan alpha -> trim to ink box -> scale long edge -> data URL.
Editor preview: renderPreview() at a 2048 master, character cached per skin+camera+pose+light, 2D layers recomposed per keystroke.
Banner pipeline: store.bannerSeed -> bannerCards(seed) -> 2 bust captures (pose per card, side rig) -> trimBust -> 2D compose at the requested width (halftone + figures + wordmark) -> canvas.toDataURL -> tile img / <a download>. Export widths 2560x1440 frame, 1546x423 strip, JPEG 0.92 fallback under the 6 MB cap.
Skin never leaves the machine; no network calls at runtime.

3. Endpoints
None. Static SPA; the renderer library runs in-browser. No fetch/XHR/API.

4. Commands
Build gate: node <pnpm.mjs> exec tsc --noEmit, then exec vite build. pnpm is not on PATH in this shell; node + pnpm.mjs paths come from the runtime dependency payload.
Verify: node C:\Users\jesmi\.dsh\skills\verify\bin\verify.mjs check --url http://127.0.0.1:4173/ --state <name>; states live in verify.states.json. States that only print numbers (custom, perf, anim, probe, banner-frame, edit-backdrop) are probes: they always throw with measurements.
Verify gotchas: `goto` substitutes $url only when a step's value is exactly "$url", so put ?r= or #c= on --url; there is no --state-file flag. `shot --selector` fails (bbox null) on .grid / .banners-grid / .download-preview -- use --selector "body" or --region. Two clicks in one eval both read the same pre-render draft, so drive one control per step with a settle between.

5. Pitfalls
- One shared SkinViewer: concurrent renders corrupt each other; the promise queue is mandatory. renderPreset, renderCutout and renderPreview share it.
- POSE BUG (fixed): playAnimation() alone does NOT touch the skeleton — only the render loop tick does — so screenshots taken right after playAnimation captured the previous batch's last pose. Symptom: every card showed the old pose over its own refreshed backdrop, and the download page matched no card. Never drop the pose frame; never trust "single keyframe so no frame needed". Same rule for any new capture path, the editor preview included.
- registerAnimation is keyed by name, so editing bones without a new name replays the first pose registered under it; poseKey(bones) exists for exactly that.
- OrbitControls clamps distance to 20..150; camera target fixed at [0,16,0]. Camera alone cannot frame a headshot: head framing comes from the 2D crop; zoom 40 + alpha trim is the full-body framing.
- Crop must stay square and inside the render: x = .5 - w/2 for a centered head (theta does not move the head sideways). The editor's crop sliders clamp x/y to 100 - w.
- PFP composition rule: judged at 64-128px. Head fills 55-60% of the crop height, face unobstructed, 3-6% margin above hair, shoulders below. Full body in a PFP = ~15px figure, all detail dies.
- Head turn cap: 3/4 turn up to ~30deg, tilt up to ~10deg. Positive head X looks down, negative looks up. Bone axes: X forward/back swing, Z sideways raise, Head Y turn, Head Z tilt.
- Bust crop means big gestures are impossible (overhead arm sits above the crop, T-pose arm outside it): personality comes from head turn/tilt, torso twist, framing.
- enableRotate/enableZoom false = no user 3D controls; poses are premade only. Do not add orbit UI.
- WebGLRendererPlugin must be registered with use() before createSkinViewer; preferredBackend "webgl" skips the WebGPU probe.
- Card previews 512px, download preview 1024, downloads 1024/2048/4096; rendering is one queue entry per grid, not one per card. Backdrops composite in 2D after a single WebGL screenshot.
- The exported PNG is opaque (bg + star baked in by cropSquare); the WebGL screenshot itself is still transparent. Do not move the backdrop into the viewer.
- Hover actions are nested inside .preset, not inside the select button (buttons cannot nest): .preset-select is the absolute full-card target, .preset-actions sits above it with z-index 2. Cards have NO focus state and NO selected border; the accent border is hover-only, so a click never leaves a lingering outline (user requirement).
- Edit page: sliders read/write the same Slot the codec serialises, steps mirror the codec rounding; updateDraft never touches the grid; Escape and Done both commit (slots by preset.id, or customSlot for a custom-* id); Download sets returnTo 'edit'.
- Editor previews coalesce: one render in flight, newest wins, final value always painted. Camera/pose/light re-render the GL character; backdrop/star/crop only recompose 2D.
- CSS collision trap: app.css is flat and later rules win on equal specificity, so a generic class (e.g. .pill, owned by the rail) silently restyles an unrelated screen. Prefix per screen.
- Toast lives in the store and is cleared by an Editor effect after 1600ms; the Hero keeps a local toast because it has no skin yet.
- Paste code is a real text input inside a form: Enter submits, clipboard paste auto-submits, invalid -> codeError ring, typing clears it.
- .paste-hero is fixed-width by design; the input needs white-space nowrap + overflow hidden + ellipsis or long codes spill.
- Download screen is a full page, not a modal: state in store.screen, Escape closes via a window keydown listener; closeDownload returns to returnTo.
- File input resets event.target.value = "" so re-uploading the same file fires onChange again.
- Randomizer scope: only bg:, star:, bgl: and light: are re-rolled; poses, cameras and crops stay literal slots.txt data, and imported codes are never re-rolled. Copy/Download encode the re-rolled slot, so the code reproduces what is on screen.
- Share codes are one-line strings: MC1|hd:x,y,z|cam:theta,phi,zoom|crop:x%,y%,w%,h%|bg:|star:|light:. Identity bones are omitted. decodePreset rejects malformed input instead of guessing (wrong version, unknown segment, non-finite numbers, crop outside 0..100, over-length) -> null -> codeError.
- Imported code becomes an extra "Shared" card selected immediately; its pose name is unique per import.
- URL hash #c=<encodeURIComponent(code)> is read once on mount; the hash is never rewritten.
- navigator.clipboard may be blocked outside HTTPS/localhost; Copy falls back to a "copy failed" toast instead of throwing.
- Renderer is a lazy dynamic import, so the main bundle stays small; the "renderer" chunk is named by manualChunks.
- No state persistence: refresh loses skin and selection except a #c= code in the URL.
- Backdrop layering is order-critical: fill -> halftone screens -> glow -> star -> vignette -> figures -> wordmark. Halftone is clipped to its area (strip or whole frame) so a strip crop never pays for pixels nobody sees.
- Pitch is a fraction of canvas WIDTH, never a pixel count: preview and export must agree proportionally. Anything below 6px per dot turns into moire, which is why the JPEG fallback bumps pitch.
- Banner heads: the crop is not the PFP crop. FIG_H = STRIP_H * 0.92 bottom-anchored leaves air above the crown; reusing the square PFP framing cuts the head flat at the strip top (the reported bug). Verify with the banner-frame headroom probe, not by eye.
- Banner invariants the probes assert: paint order bg>left>right>text, 16:9 frame, busts flush to the strip edges (<=1px), wordmark centred, strip inside the frame. The glyph-centroid drift metric is loose (12px) because box centring is the real instrument.
- One .refresh owns all four banner cards: seed bump -> new poses + specs for every card. Never per-card refresh buttons, and never a refresh that also re-rolls the PFPs.
- Dev server on 5173 can serve stale transforms (OneDrive breaks the Vite watcher): the built preview on 4173 and the on-disk source disagreeing means restart vite, not edit code. Never restart it yourself.
- .banners-head must contain the refresh button beside the title, level with it and the same width as the PFP refresh; the banner-section probe counts exactly 1.
